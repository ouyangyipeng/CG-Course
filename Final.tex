以下题目引用自中山大学计算机网络实验考试指导书\cite{Guidance}：

\begin{figure}[H]

请参照以上网络拓扑图，利用实验室已有设备完成相应的实验任务，记录实验中的关键信息以及截
图，并呈现在实验报告中。网络拓扑说明：

\begin{enumerate}
    \item 路由器 R1 与 R2 通过一个网口互联；
    \item 交换机 S1 与 S2 分别通过网口与路由器 R1 连接；
    \item 交换机 S1 与 S2 先连接一条线，完成 VLAN 和 RSTP 设置后再连接另一条网线。（请注意交换机环路连接引起的网络风暴）；
    \item 主机按图中方案与交换机及路由器连接，主机数量不够，可以动态调配主机与中继设备的连接，或通过自带笔记本来实现。
    \item 请根据任务需要自定义主机、网段的地址和掩码，并在实验报告中明确地址信息。
\end{enumerate}

\textbf{实验任务说明：}

\begin{enumerate}
    \item (20 分) 设计并实现方案解决图中 S1 与 S2 之间插上两条网线后产生的网络风暴问题，请在实验报告中提供方案和实验结果。
    \item (20 分) 按图中完成 VLAN 配置，要求 H1 与（H2，H4）能够相互 ping 通，不同 VLAN 要求通过路由器连通，请在实验报告中提供方案和实验结果。
    \item (20 分) R1 与 R2 之间采用 OSPF 路由协议。要求所有主机能够两两相互 ping 通。
    \item (20 分) 实现符合以下要求的访问控制：
    \begin{itemize}
        \item 在 08:00~11:00 时间段内，H1 与 H5 可以互访，但是不允许 H1 与 H3 互通；H2 与 H3 可以互访，但是不允许 H2 与 H5 互通。
        \item 在 14:00~17:00 时间段内，H1 与 H3 可以互访，但是不允许 H1 与 H5 互通；H2 与 H5 可以互访，但是不允许 H2 与 H3 互通。
        \item 其余时段，禁止 H1 与（H3，H5）的互通，禁止 H2 与（H3，H5）的互通。
        \item 在所有时段，H1、H2 与 H4 之间的互通不受 ACL 限制；H3 和 H5 之间的互通不受 ACL 限制。H4 可以全时段自由与任意主机进行双向互通。
    \end{itemize}
    \item (20 分) 基于 UDP 或 TCP 套接字编程技术，实现 H1（发送端）和 H5（接收端）的数据发送。发送数据包括：图像和文字（建议把下图存为 BMP 格式图像后用于传送）。请在实验报告中呈现数据经过中继设备时的特点，并比较接收结果和发送端原始版本之间的差异。

\section{【任务一】解决网络风暴}

看图可以发现，S1与S2之间通过双链路互联，这其实就跟之前那次实验中我们做观察风暴的场景类似。如果不启用生成树协议，广播帧（如ARP请求）将在S1和S2之间无限循环，形成广播风暴。这将导致交换机CPU占用率飙升至100\%，MAC地址表震荡，最终导致整个局域网瘫痪。因此，必须在S1和S2上启用RSTP，以确保网络的稳定性和可靠性。

\subsection{配置思路}

解决这个问题的核心在于启用rstp和vlan，我们的操作顺序如下：

\begin{enumerate}
    \item \textbf{物理连接控制}：为了防止在配置未完成时发生广播风暴，我们首先\textbf{只连接一条}S1与S2之间的级联线。
    \item \textbf{VLAN创建与划分}：在S1和S2上创建VLAN 10和20，并将连接主机的端口划入相应VLAN。
    \item \textbf{RSTP配置}：全局开启RSTP模式，确保协议生效。
    \item \textbf{Trunk配置}：配置级联端口为Trunk模式，允许所有相关VLAN通过。
    \item \textbf{冗余连接与验证}：连接第二条级联线，观察RSTP的收敛过程。
\end{enumerate}

\begin{itemize}

\end{itemize}

\begin{myquote}
    \textbf{思考}：为什么 S2 成为了根桥？（在写报告的时候想到了这个问题）

\end{myquote}

\subsection{故障模拟与收敛测试}

为了进一步验证 RSTP 的可靠性，我们进行了一次故障模拟测试。这一步我们上次进行rstp实验的时候好像没做，这次正好有机会验证一下。

\textbf{测试步骤}：
\begin{enumerate}
    \item 保持双链路连接，确认 G0/0/23 处于 Discarding 状态。
    \item 拔掉 S1 的 G0/0/22 网线（模拟主链路故障）。
    \item 观察 S1 的 G0/0/23 端口状态变化。
\end{enumerate}

\textbf{观察结果}：

几乎在拔线的瞬间，G0/0/23 端口的状态立即从 \texttt{DISCARDING} 变为 \texttt{FORWARDING}。

\begin{lstlisting}[language=HuaweiConfig, caption={故障切换后的 STP 状态}]
[S1] display stp brief
 MSTID  Port                        Role  STP State     Protection
   0    GigabitEthernet0/0/1        DESI  FORWARDING      NONE
   0    GigabitEthernet0/0/23       ROOT  FORWARDING      NONE
\end{lstlisting}

\textbf{原理分析}：

这是 RSTP 的 UplinkFast 机制在起作用（虽然好像标准 RSTP 不叫这个名字来着）。当根端口失效时，如果存在替代端口Alternate Port，交换机会立即将替代端口切换为根端口并进入转发状态，无需等待 30 秒的侦听和学习时间。这也另一方面验证了理论课学的说冗余链路 RSTP 在应对链路故障时的高可用性。

\subsection{边缘端口的优化}

在实验中我们发现，连接 PC 的端口（如 G0/0/1）在启用 RSTP 后，有时候插拔网线仍需等待一小段时间才能转发，跟之前拔插马上就可以用的情况不太一样。

我们在网上查了一圈，发现这是因为这些端口默认被视为普通 STP 端口，需要经历 Proposal/Agreement 过程。为了方便后面的使用，我们将连接 PC 的端口配置为边缘端口：

\begin{lstlisting}[language=HuaweiConfig, caption={配置边缘端口}]
[S1] interface GigabitEthernet 0/0/1
[S1-GigabitEthernet0/0/1] stp edged-port enable
[S1-GigabitEthernet0/0/1] quit
\end{lstlisting}

配置后，该端口 Up 后立即进入 Forwarding 状态，不再发送 TC (Topology Change) BPDU，从而避免了不必要的全网拓扑震荡。

\section{【任务四】基于时间的 ACL 访问控制}

\subsection{需求分析与策略设计}
这一个任务要求我们实现基于时间的精细化访问控制，相比于我们之前实验课做过的 ACL，Time-range ACL 引入了时间维度，使得网络策略更加灵，但也相应的更难配了。需求矩阵如下：
\begin{itemize}
    \item \textbf{上午 (08:00-11:00)}：H1 可访 H5，禁访 H3；H2 可访 H3，禁访 H5。
    \item \textbf{下午 (14:00-17:00)}：H1 可访 H3，禁访 H5；H2 可访 H5，禁访 H3。
    \item \textbf{其他时间}：禁止 H1/H2 访问 H3/H5。
    \item \textbf{全时段允许}：H1/H2/H4 互通；H3/H5 互通。
\end{itemize}

\begin{myquote}
    \textbf{策略设计难点}：ACL 的匹配规则是“顺序匹配，命中即止”。因此，我们需要将具体的、特殊的规则放在前面，将通用的、默认的规则放在后面。
    此外，为了防止默认的 \texttt{deny} 规则误伤 VLAN 间流量（H1-H2），我们需要在 ACL 最前端显式放行 VLAN 10 和 VLAN 20 之间的流量。
\end{myquote}

\subsection{ACL 匹配逻辑深度解析}
为了确保 ACL 策略的正确性，我们必须深入分析 ACL 的匹配机制。ACL 的匹配遵循“顺序优先”原则，具体取决于设备实现。在华为设备上，我们查到是默认遵循 \textbf{Config 模式}，即按照 Rule ID 从小到大依次匹配。

比方说我们有以下规则集作为错误示例：
\begin{lstlisting}[language=HuaweiConfig, caption={ACL 错误示例}]
rule 10 deny ip source 192.168.20.1 0 destination 192.168.50.5 0
rule 20 permit ip source 192.168.20.1 0 destination 192.168.50.5 0 time-range morning
\end{lstlisting}
\textbf{分析}：
如果当前时间是上午 09:00，H1 (20.1) 访问 H5 (50.5)。
\begin{itemize}
    \item 系统首先检查 Rule 10。
    \item 源 IP 匹配，目的 IP 匹配。
    \item 动作是 Deny。
    \item \textbf{结果}：数据包被丢弃。系统不再检查 Rule 20。
\end{itemize}
这意味着，即使 Rule 20 允许了该流量，由于 Rule 10 排在前面且匹配成功，Rule 20 永远不会生效。

\textbf{正确策略}：
必须将更具体的、带有时间限制的规则放在前面，将通用的、无时间限制的规则放在后面。
\begin{lstlisting}[language=HuaweiConfig, caption={ACL 正确策略示例}]
rule 5 permit ip source 192.168.20.1 0 destination 192.168.50.5 0 time-range morning
rule 55 deny ip source 192.168.20.1 0 destination 192.168.50.5 0
\end{lstlisting}
\textbf{分析}：
\begin{itemize}
    \item \textbf{上午 09:00}：
    \begin{itemize}
        \item 检查 Rule 5：源/目 IP 匹配，时间范围匹配（当前在 morning 范围内）。
        \item 动作：Permit。
        \item 结果：放行。
    \end{itemize}
    \item \textbf{晚上 20:00}：
    \begin{itemize}
        \item 检查 Rule 5：源/目 IP 匹配，但时间范围\textbf{不匹配}（当前不在 morning 范围内）。
        \item 规则不生效，继续检查下一条。
        \item ... (中间规则不匹配) ...
        \item 检查 Rule 55：源/目 IP 匹配，无时间限制。
        \item 动作：Deny。
        \item 结果：丢弃。
    \end{itemize}
\end{itemize}
通过这种“特例在前，通用在后”的排序方式，我们才能实现预期的分时段控制。下面我们也通过这个思路来配置 ACL。

\subsection{ACL 配置实施}

首先定义上下午两个时间段：

\begin{lstlisting}[language=HuaweiConfig, caption={定义时间段}]
[R1] time-range morning 08:00 to 11:00 daily
[R1] time-range afternoon 14:00 to 17:00 daily
\end{lstlisting}

接着定义高级 ACL 3027：

\begin{lstlisting}[language=HuaweiConfig, caption={ACL 3027 定义}]
[R1] acl 3027
\end{lstlisting}

然后我们在最前面放行 VLAN 间流量（其实这一步是写完后面那堆规则才想到的），主要是为了防止后续的 deny 规则阻断内网互通：

\begin{lstlisting}[language=HuaweiConfig, caption={VLAN 间互访规则}]
rule 1 permit ip source 192.168.10.0 0.0.0.255 destination 192.168.20.0 0.0.0.255
rule 2 permit ip source 192.168.20.0 0.0.0.255 destination 192.168.10.0 0.0.0.255
\end{lstlisting}

然后我们添加上午的规则，主要有四条，分别是允许H1访H5，禁止H1访H3，允许H2访H3，禁止H2访H5：

\begin{lstlisting}[language=HuaweiConfig, caption={上午规则}]
# H1 (VLAN 20) -> H5 (50.5): Permit
rule 5 permit ip source 192.168.20.1 0 destination 192.168.50.5 0 time-range morning
# H1 -> H3 (30.3): Deny
rule 10 deny ip source 192.168.20.1 0 destination 192.168.30.3 0 time-range morning
# H2 (VLAN 10) -> H3: Permit
rule 15 permit ip source 192.168.10.2 0 destination 192.168.30.3 0 time-range morning
# H2 -> H5: Deny
rule 20 deny ip source 192.168.10.2 0 destination 192.168.50.5 0 time-range morning
\end{lstlisting}

接着是下午的规则，同样四条，分别是允许H1访H3，禁止H1访H5，允许H2访H5，禁止H2访H3：

\begin{lstlisting}[language=HuaweiConfig, caption={下午规则}]
# H1 -> H3: Permit
rule 25 permit ip source 192.168.20.1 0 destination 192.168.30.3 0 time-range afternoon
# H1 -> H5: Deny
rule 30 deny ip source 192.168.20.1 0 destination 192.168.50.5 0 time-range afternoon
# H2 -> H5: Permit
rule 35 permit ip source 192.168.10.2 0 destination 192.168.50.5 0 time-range afternoon
# H2 -> H3: Deny

\section{【任务五】网络套接字编程}

\subsection{协议设计}
本任务要求基于 TCP 协议实现 H1 (Client) 向 H5 (Server) 发送文本和图像数据。为了确保数据在网络传输中的完整性以及解决 TCP 粘包问题，我们设计了一个简单的应用层通信协议。

通信双方约定采用“长度前缀”的方式传输变长数据。具体流程如下：
\begin{enumerate}
    \item 建立 TCP 连接。
    \item 发送文本数据长度（4字节，大端序 unsigned int）。
    \item 发送文本数据内容（UTF-8 编码）。
    \item 发送图像数据长度（4字节，大端序 unsigned int）。
    \item 发送图像数据内容（二进制）。
    \item 发送图像的 MD5 校验码（32字节，UTF-8 编码）。
    \item 服务器校验 MD5 并返回确认信息。
\end{enumerate}

\subsection{服务端 (Server) 代码实现}
服务端代码 \texttt{server.py} 运行在 H5 上，负责监听端口、接收数据并保存文件。

\subsubsection{辅助函数与初始化}
首先引入必要的库，定义服务器 IP、端口及保存路径。\texttt{calculate\_md5} 用于计算数据的哈希值以校验完整性。\texttt{recv\_all} 函数是 TCP 编程中的关键，用于确保完整接收指定长度的数据，防止因网络分片导致的接收不全。

\begin{lstlisting}[language=Python, caption={server.py: 辅助函数}]
import socket
import struct
import hashlib
import os

SERVER_IP = '0.0.0.0'
SERVER_PORT = 9999
SAVE_DIR = 'received_files'

def calculate_md5(data):
    return hashlib.md5(data).hexdigest()

def recv_all(sock, n):
    data = b''
    while len(data) < n:
        packet = sock.recv(n - len(data))
        if not packet:
            return None
        data += packet
    return data
\end{lstlisting}

\subsubsection{主逻辑与数据接收}
\texttt{start\_server} 函数初始化 Socket，绑定地址并开始监听。服务器采用循环方式处理客户端连接。连接建立后，服务器严格按照协议顺序接收数据：首先接收4字节的文本长度，解析后接收对应长度的文本内容并保存；接着接收图像长度和图像数据。

随后接收客户端发送的 MD5 校验码，服务器自行计算接收到的图像数据的 MD5 并进行比对，验证数据传输的正确性。最后发送 ACK 确认。

\begin{lstlisting}[language=Python, caption={server.py: 主逻辑}]
def start_server():
    if not os.path.exists(SAVE_DIR):
        os.makedirs(SAVE_DIR)

    # 创建 TCP Socket
    server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server_socket.bind((SERVER_IP, SERVER_PORT))
    server_socket.listen(1)
    
    print(f"[*] Server listening on {SERVER_IP}:{SERVER_PORT}")

    while True:
        client_socket, addr = server_socket.accept()
        print(f"[+] Accepted connection from {addr}")

        try:
            # 1. 接收文本长度 (4 bytes)
            raw_text_len = recv_all(client_socket, 4)
            if not raw_text_len: break
            text_len = struct.unpack('!I', raw_text_len)[0]

            # 2. 接收文本内容
            text_data = recv_all(client_socket, text_len)
            text_content = text_data.decode('utf-8')
            print(f"[R] Received Text:\n{text_content}\n")
            
            # 保存文本
            with open(os.path.join(SAVE_DIR, 'received_text.txt'), 'w', encoding='utf-8') as f:
                f.write(text_content)

            # 3. 接收图片长度 (4 bytes)
            raw_img_len = recv_all(client_socket, 4)
            img_len = struct.unpack('!I', raw_img_len)[0]

            # 4. 接收图片内容
            print(f"[*] Expecting image size: {img_len} bytes")
            img_data = recv_all(client_socket, img_len)
            
            # 5. 接收客户端计算的 MD5 (32 bytes hex string)
            client_md5 = recv_all(client_socket, 32).decode('utf-8')

            # 验证完整性
            server_md5 = calculate_md5(img_data)
            print(f"[V] Client MD5: {client_md5}")
            print(f"[V] Server MD5: {server_md5}")

            if client_md5 == server_md5:
                print("[+] Integrity Check: PASSED")
            else:
                print("[-] Integrity Check: FAILED")

            # 保存图片
            save_path = os.path.join(SAVE_DIR, 'received_image.bmp')
            with open(save_path, 'wb') as f:
                f.write(img_data)
            print(f"[+] Image saved to {save_path}")

            # 发送确认
            client_socket.send(b"ACK: Transfer Complete")

        except Exception as e:
            print(f"[-] Error: {e}")
        finally:
            client_socket.close()
            print("[-] Connection closed")
            break

if __name__ == '__main__':
    start_server()
\end{lstlisting}

\subsection{客户端 (Client) 代码实现}
客户端代码 \texttt{client.py} 运行在 H1 上，负责读取本地数据并发送给服务器。

\subsubsection{配置与准备}
定义目标服务器 IP（H5 的 IP 地址）和端口，以及待发送的文本和图片路径。

\begin{lstlisting}[language=Python, caption={client.py: 配置与准备}]
import socket
import struct
import hashlib
import os
import sys

SERVER_IP = '192.168.50.5'
SERVER_PORT = 9999
IMAGE_PATH = 'image.bmp'

TEXT_CONTENT = """Dr. Sun Yat-sen ordered the merger of several colleges and universities in February 1924, into the National Guangdong University, which was renamed as National Sun Yat-sen University in his memory in August 1926."""

def calculate_md5(data):
    return hashlib.md5(data).hexdigest()
\end{lstlisting}

\subsubsection{连接与发送逻辑}
\texttt{start\_client} 函数首先检查图片文件是否存在，然后建立连接。读取图片数据并计算 MD5 后，依次发送：文本长度、文本内容、图片长度、图片内容、MD5 校验码。注意使用 \texttt{struct.pack('!I', ...)} 将长度打包为网络字节序（大端）。

\begin{lstlisting}[language=Python, caption={client.py: 发送逻辑}]
def start_client():
    # 检查图片是否存在
    if not os.path.exists(IMAGE_PATH):
        print(f"[-] Error: {IMAGE_PATH} not found. Please place a BMP file named '{IMAGE_PATH}' in the same directory.")
        # with open(IMAGE_PATH, 'wb') as f:
        #     f.write(b'BM' + b'\x00'*52) # Minimal BMP header
        # print(f"[!] Created dummy {IMAGE_PATH} for testing.")

    try:
        client_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        print(f"[*] Connecting to {SERVER_IP}:{SERVER_PORT}...")
        client_socket.connect((SERVER_IP, SERVER_PORT))
        print("[+] Connected.")

        # 准备数据
        text_bytes = TEXT_CONTENT.encode('utf-8')
        with open(IMAGE_PATH, 'rb') as f:
            img_bytes = f.read()
        
        img_md5 = calculate_md5(img_bytes)

        # 1. 发送文本长度 (4 bytes)
        print(f"[*] Sending Text ({len(text_bytes)} bytes)...")
        client_socket.send(struct.pack('!I', len(text_bytes)))
        
        # 2. 发送文本内容
        client_socket.send(text_bytes)

        # 3. 发送图片长度 (4 bytes)
        print(f"[*] Sending Image ({len(img_bytes)} bytes)...")
        client_socket.send(struct.pack('!I', len(img_bytes)))

        # 4. 发送图片内容
        client_socket.sendall(img_bytes)

        # 5. 发送 MD5 校验和
        print(f"[*] Sending MD5: {img_md5}")
        client_socket.send(img_md5.encode('utf-8'))

        # 接收确认
        response = client_socket.recv(1024)
        print(f"[S] Server Response: {response.decode()}")

    except ConnectionRefusedError:
        print("[-] Connection refused. Is the server running?")
    except Exception as e:
        print(f"[-] Error: {e}")
    finally:
        client_socket.close()

if __name__ == '__main__':
    if len(sys.argv) > 1:
        SERVER_IP = sys.argv[1]
    start_client()
\end{lstlisting}

\section{实验总结}

通过本次实验，我们深入理解并实践了各个网络技术点，包括 VLAN 配置、OSPF 动态路由协议、基于时间的 ACL 访问控制以及基于 TCP 的网络套接字编程。具体总结如下：

\begin{itemize}

    \item \textbf{网络套接字编程}：通过 Python 实现了基于 TCP 的客户端-服务器通信，设计了简单的应用层协议，解决了数据完整性和粘包问题。实际运行验证了程序的功能和稳定性。
\end{itemize}
